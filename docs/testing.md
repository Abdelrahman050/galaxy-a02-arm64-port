# Test and Evidence Boundaries

## Recorded project tests

- The AArch64 kernel was built, then rebuilt in an independent clean output. Both builds completed; config and `System.map` matched, but `Image` and `vmlinux` differed by SHA-256. This is a successful rebuild, not bit-identical reproducibility or a boot test.
- Kernel patches 0001–0003 passed a historical dry-run apply check against the exact Samsung source copy. Patches 0004–0007 compiled and linked in isolated build outputs. Patch 0008 passed an AArch64 object-only build and offline layout checks. Patches 0009–0010 were reviewed only.
- PowerVR changes were compiled and linked; no GPU or display test was run.
- Device-tree comparisons covered all nodes, properties, and memory reservations for the selected official merged trees; only the intended PMU compatible property differed. DTBO r00/r01/r06 outputs matched byte-for-byte. No device boot was performed.
- Static LK analysis established that a K64 branch is present. It did not establish runtime branch selection or secure-world acceptance.
- The offline boot layout was unsigned. Size and header checks are arithmetic/static checks only.
- The newest USB-ACM boot layout was re-read and its full SHA-256/size, Android v2 fields, page-aligned offsets, kernel gzip/decompressed Image, base-FDT table, initramfs gzip/CPIO, and static AArch64 ELF header were checked offline. This did not exercise LK, UDC, a COM port, or the phone.
- During PR review, source inspection found the retained candidate's ConfigFS writes were not safely formatted for the upstream Linux v4.14 base-autodetection parser. `init.c` was corrected to emit `0x`-prefixed numeric values; `build.sh` requires an explicit authorized VID, assigned PID, unique serial, and a fresh output directory; the PowerShell reader waits for exact PnP identity, checks it before and after opening the port, and saves a local evidence record. The revised `init.c` passed an isolated Clang 21.1.6 cross compile/link with synthetic compile-time identity macros (5,520-byte ELF64, `EM_AARCH64=183`); the temporary ELF was removed. The PowerShell source passed AST parsing; all repository Python tests passed. `bash -n` could not run in the local Windows/WSL environment and is now an explicit CI step, pending the updated PR run. Windows PnP behavior remains untested. These newer sources were not built into the existing candidate. Any compile/syntax checks apply only to source and do not repair or validate the retained image.

## Tests included with this staging tree

`tests/test_repo_audit.py` exercises positive and negative cases for safe text, firmware-image exclusion, secret/local-path patterns, checksum mismatch/coverage, exclusion of untracked local-only inputs, rejection if a local-only path enters the Git index, and rejection of a `.gitignore`-excluded image if it is force-added. `tests/test_usb_probe_policy.py` checks that probe builds have no default USB identity, require authorized identity inputs, refuse non-empty output directories, and that the host reader filters by exact present PnP VID/PID/serial before opening a COM port and records evidence. These are static policy assertions, not a PowerShell PnP simulation. `tests/test_device_tree_safety.py` verifies that three device-tree helpers reject output paths that overlap read-only source/firmware inputs before writing. `tests/test_prepare_stock_port.py` uses synthetic DTS inputs to verify correct PMU-only editing, source immutability, output isolation, and rejection of binary, malformed, wrong-SoC, ambiguous-PMU, and incomplete inputs. `tests/test_build_helper_safety.py` verifies the kernel helper refuses source/output overlap and a non-empty output directory before running `make`. `scripts/repo_audit.py` checks the final staged tree and SHA-256 manifest. These repository hygiene checks do not validate Linux runtime behavior, device-tree semantics without exact FDT inputs, signature trust, or hardware boot.

The `kernel_qa.py`, `fdt_diff.py`, `flash_readiness_gate.py`, and device-tree scripts are included for future use against separately supplied inputs. The revised probe C source was not cross-compiled in this review, and the Bash helper was not syntax-checked or run: WSL/Git Bash execution was denied by the Windows environment, and the required local kernel `gen_init_cpio`/recorded Clang bundle were not available. This repository does not include copyrighted firmware, kernel source, or generated binaries needed to rerun the full Phase 2 tests.

The initial repository commit had one successful GitHub Actions run on 2026-10-20; details and its exact commit are recorded in [`ci.md`](ci.md). That workflow verifies repository hygiene, Python syntax, and synthetic audit tests only. It does not compile the kernel or probe, inspect firmware, or test a device.
